/verify
코드 변경이 실제로 요구한 대로 동작하는지 확인하는 Built-in Skill입니다.
테스트나 타입 검사 결과에만 의존하지 않고, 프로젝트의 앱을 직접 빌드하고 실행한 뒤 실제 결과를 관찰하여 기능이 정상적으로 동작하는지 검증합니다.
웹 앱에서는 Claude in Chrome과 연동하여 Claude가 Chrome에서 실제 페이지를 열고, 클릭하고, 입력 등의 동작을 수행하며 결과를 확인할 수 있습니다.
https://code.claude.com/docs/ko/commands

Plan Mode
/plan을 입력하면 Claude Code가 Plan Mode(계획 모드) 로 전환됩니다.
Plan Mode에서는 Claude가 파일을 읽고 코드베이스를 탐색할 수 있지만 소스 코드를 수정하지는 않습니다. 필요하다면 계획을 확정하기 전에 질문도 할 수도 있습니다.
그래서 여러 파일을 건드리는 리팩터링이나 구현 방향부터 확인하고 싶은 복잡한 작업에 특히 유용합니다.

Permission Mode
Claude Code가 작업할 때 어느 정도까지 자율적으로 행동할 수 있는지 설정하는 모드입니다.

- Manual mode: 파일 수정이나 명령 실행 전에 사용자에게 확인받으면서 작업
- Accept edits on: 파일 수정은 자동 허용하고, 그 외 터미널 명령 등은 필요할 때 확인
- Plan mode: 코드는 수정하지 않고 읽고 분석해서 계획만 수립
- Auto mode: Claude가 필요한 작업을 자율적으로 수행하고 내부 안전 검사를 통해 허용/거부

* interview-me: 구현 전에 질문을 통해 사용자의 실제 요구사항을 구체화합니다.
* /spec: 구현할 기능의 요구사항과 범위를 명확하게 정의합니다.
* /plan: 구현 방법을 작은 작업 단위로 계획합니다.
* /build: 계획을 기반으로 기능을 점진적으로 구현합니다.
* /test: 구현한 기능이 제대로 동작하는지 테스트하고 검증합니다.
* /review: 코드 품질을 검토하고 개선합니다.
* /ship: 배포 전 필요한 사항을 최종적으로 확인합니다.


Claude Code 코드 검토 및 품질 관리

Claude가 코드를 수정한 후 변경 내용을 확인하고, 코드 품질과 보안을 검토하기 위한 기능들입니다.
* /diff: 변경된 코드를 확인
* /simplify: 불필요한 복잡성을 줄이고 코드를 더 깔끔하게 개선
* /code-review: 버그나 잘못된 동작이 없는지 검토
* /security-review: 보안 취약점이 없는지 검토
* /context: 현재 컨텍스트 사용량과 어떤 정보가 컨텍스트를 차지하고 있는지 확인


Sessions
Session은 Claude Code와 한 번 시작해서 이어가는 작업 대화 단위이며, 프로젝트 경로와 연결되어 관리됩니다.
실제 Session 기록은 ~/.claude/projects/ 아래에 프로젝트 경로별로 구분되어 저장됩니다.

/resume
이전에 작업했던 Session을 불러와 기존 대화와 작업 맥락을 이어서 작업할 수 있습니다.
https://code.claude.com/docs/ko/common-workflows#resume-previous-conversations

/rename
현재 Session에 알아보기 쉬운 이름을 지정하여 나중에 /resume으로 쉽게 찾아 이어서 작업할 수 있습니다.


Agent View
Claude Code에서 여러 Agent 작업의 진행 상태를 한눈에 확인하고 관리할 수 있는 화면입니다.

* Needs input: 사용자 입력이 필요한 작업
* Working: 현재 실행 중인 작업
* Completed: 작업이 완료된 상태
여러 작업을 동시에 진행할 때 각 작업의 상태를 빠르게 파악하고 관리하는 데 유용합니다.

Worktrees
Git의 Worktree 기능을 활용하여 현재 작업 공간과 분리된 별도의 작업 공간과 브랜치에서 Claude가 작업할 수 있도록 합니다.
현재 작업에 영향을 주지 않고 새로운 기능을 개발하거나, 여러 Agent가 서로 다른 작업을 병렬로 진행할 때 유용합니다.
https://code.claude.com/docs/ko/common-workflows#run-parallel-sessions-with-worktrees
